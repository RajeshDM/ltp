Tables we will report

The story: a policy that takes the domain description as input, alongside state and goal, chooses ground actions in PDDL domains it never saw in training, with no search. What makes it work is binding each applicable ground action to the parts of the domain description it instantiates.

One policy runs zero-shot on unseen domains, because the domain is data, not architecture.

Representations, explained

All systems share one pipeline: a PDDL state becomes a graph, a graph neural network encodes it, and a GRU decoder picks an action schema, then each of its arguments. They differ only in the graph. The table lists what each graph contains; the explorer below draws them on one Miconic state.

    Decoder and constrained decoding

    The decoder scores schema nodes against its hidden state and keeps the best 2; for each, it scores object nodes for the first argument and keeps the best 3, then the next argument given the first, and so on. The beam is not pruned, so a step proposes up to 2 × 3arity candidates (Miconic 18, Rovers up to 1,458). The executor takes the best-ranked candidate that is applicable and not a revisit, and stops if none is applicable.

    Unconstrained

    Each argument's top 3 objects are chosen by score alone. In Rovers, where actions take up to six mutually dependent arguments, most candidates are impossible combinations: GABAR's top candidate was applicable on 25% of steps, GADAR's on 44%. When no candidate is applicable the episode ends.

    Constrained (GABAR_CONSTRAINED_DECODE=1)

    Before each argument's top-3, objects that no applicable ground action allows in that slot (given the arguments already chosen) get score −∞. Scores still decide among legal objects; every candidate is applicable. Uses only the applicable ground actions the graph is built from. Batched and sequential decoders give identical candidate lists (0 mismatches on 600+ Rovers states) and identical results.

    Typed vs untyped domains

    Six suite domains declare PDDL types (Blocks, Gripper, Miconic, Visitall, Spanner, Rovers); Grid and Logistics spell types as unary predicates. GABAR never mixes them. GADAR does, so its lifted layer compiles declared types into unary static predicates: a parameter ?x - block becomes a precondition (block ?x), and every object gets a has_type edge to its type's symbol node. The two spellings then produce the same domain description (unit test test_typed_and_predicate_typed_domains_agree_structurally).

    One residual difference: in an untyped domain each type fact, such as (truck t1), is also a ground literal node in the state graph. E6 tests whether that matters, using behaviour-identical typed twins of Grid and Logistics (tools/convert_to_typed.py; Logistics' airport stays a predicate to avoid a type hierarchy).

    Checkpoint selection and seeds

    Why the old rule failed

    • Validation was 10% of training states, split after pooling: same problems, often one step apart.
    • Validation was training-sized; we report coverage on problems 2–8× larger.
    • Epoch losses are sums over batches and training is ~9× validation, so "combined loss" was effectively lowest training loss.
    • Coverage swings between nearby checkpoints: batch-64 Miconic was 34.5% at epoch 490 and 100% at epoch 470.

    The new rule

    • Snapshot every 50 epochs (10 per run).
    • Two validation signals: teacher-forced loss on Val-ID (same size, unseen problems) and on Val-OOD (larger); coverage on Val-OOD by rollout.
    • Report the snapshot with best Val-OOD coverage (ties → earlier), fixed before any test number is read. Same rule for GABAR.
    • 3 seeds, mean ± std.
    • Zero-shot: no data from the target domain at all, selection on the training domains' validation sets.

    What we found, and when

    1. Nov 12Single-effect schemas dropped. pddlgym stores a one-effect schema's effect as a bare literal; the featurizer read it as "no effects". Miconic board and Rovers calibrate lost their add effects and chain edges. Fixed; models and caches versioned (fx). Every seven-domain GADAR/BIND model from September is affected.
    2. Nov 13Table 2 cell provenance. A checkpoint best under two metrics was tested once; the second metric's cell was filled from an older dump. Fixed; submitted Table 2 unchanged except one cell (95.4 → 95.5). Featurizer audit tool written (tools/audit_featurizer.py).
    3. Nov 14Negative preconditions lost their sign in the lifted layer, inverting chain edges through them. Fixed without new feature columns; no suite domain has one.
    4. Nov 26GABAR does not reproduce through our pipeline on Blocks (52.5), Logistics (0.0), Rovers (7.4); optimal plans do not help. Rule baselines: the goal-feature rule beats GADAR zero-shot on Blocks.
    5. Nov 26Policies lose to random on Rovers because they propose actions that do not exist. Constrained decoding: Rovers 7.4 → 46.3 (GABAR), 20.4 → 57.4 (GADAR); Logistics GADAR 3.1 → 36.5. The batched evaluator silently ignored the flag; a batched constrained decoder was written and matches exactly.
    6. Nov 26–27Batch size and learning rate. Batch 16 lifted Miconic 44.5 → 100 but hurt Blocks, Spanner, Rovers; lr 2e-3 diverges. Then the batch-64 Miconic run turned out to hold a 100% checkpoint already: the problem was the checkpoint rule and single-seed noise.
    7. Nov 27Protocol defects. Validation split by state, training-sized validation, Rovers test leakage (4 problems), Blocks test sizes, training sets differing from the GABAR paper's Table 1 in 7 of 8 domains. New protocol designed and being built.
    8. Nov 27Cluster trap. Fast Downward does not run on the older cn-b*/cn-c* share nodes; it "fails" every problem in 0.4 s. Excluded; the solver now aborts on that signature.
